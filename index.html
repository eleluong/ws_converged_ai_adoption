Introduction

Nền tảng ConnectED: Kỷ nguyên mới của Soạn giáo án AI

ConnectED là hệ sinh thái AI-native đầu tiên tại Việt Nam thiết kế chuyên biệt cho K-12. Chúng tôi ánh xạ các phương pháp sư phạm kinh điển thành hệ thống đa tác nhân giải quyết khối lượng công việc giáo viên.

Mô hình Thiết kế Chỉ dẫn ADDIE

Vòng lặp cải tiến liên tục tích hợp AI tại mọi miền tính toán sư phạm.

search

1. Analysis (Phân tích)

Miền tính toán: Xử lý sách giáo khoa và quy chế để sinh đồ thị tri thức.

Input: Chương trình GDPT 2018, file sách giáo khoa PDF thô.

Output JSON: Cấu trúc khái niệm cốt lõi (Core Concepts), năng lực cần đạt và kiến thức tiền đề (prerequisites).

architecture

2. Design (Thiết kế)

Miền tính toán: Phân bổ bài học 45 phút tiêu chuẩn và lập sơ đồ đánh giá năng lực Bloom's.

Input: Concept Graph từ giai đoạn Analysis.

Output JSON: Bài giảng phác thảo (lesson blueprint), cấu trúc hoạt động và bộ tiêu chuẩn kiểm tra đánh giá.

code_blocks

3. Development (Phát triển)

Miền tính toán: Triển khai học liệu thực tế. Áp dụng phương pháp kịch bản trước (Script-First Approach) tạo thoại thuyết minh trước hình ảnh.

Input: Lesson blueprint đã được duyệt.

Output: Chuỗi slide giáo án hoàn chỉnh, kịch bản hướng dẫn thực hành lab STEM.

rocket_launch

4. Implementation (Triển khai)

Miền tính toán: Hiển thị giao diện soạn bài cho giáo viên phê duyệt hoặc xuất slide trực tiếp sang các nền tảng giảng dạy LMS.

Input: Giáo án, kịch bản học liệu hoàn thiện.

Output: Slide bài giảng tương tác, hướng dẫn thí nghiệm ảo hoạt động tốt.

rate_review

5. Evaluation (Đánh giá)

Miền tính toán: Phân tích phản hồi học tập từ người dạy và người học để tự động điều chỉnh kế hoạch bài giảng ở các lớp học sau.

Input: Nhật ký sử dụng slide, kết quả làm bài tập của học sinh.

Output JSON: Đề xuất sửa đổi prompt hoặc nội dung hoạt động bị chênh lệch thời gian.

Module 02

Agentic AI Stack: Khung Kiến Trúc AI Hiện Đại

Hiểu sâu 5 lớp cốt lõi cấu tạo nên các Agent AI tự chủ trong môi trường doanh nghiệp và sản xuất thực tế.

Phân tích chi tiết 5 lớp kiến trúc

psychology

1. Orchestration & State Management

Lớp quản lý trạng thái, vòng đời thực thi, định hướng phân rã nhiệm vụ và phối hợp đa tác nhân.

So sánh các Orchestration Frameworks:

Framework Điểm mạnh Phù hợp nhất
LangGraph Kiểm soát đồ thị tuần hoàn Workflows phức tạp
CrewAI Hội thoại định hướng vai trò Nhóm đa tác nhân
Custom Machine Đảm bảo 100% schema JSON Hệ thống sản xuất thực tế
route

2. Reasoning Core & Model Routing

Định tuyến ngữ nghĩa (Semantic Routing) yêu cầu người dùng đến các mô hình lớn/nhỏ phù hợp để tối ưu chi phí và tốc độ.

Định tuyến Mô hình phân cấp (Tiered Model Routing):

  • • Frontier Large (Claude 4.6 Sonnet): Lập kế hoạch cấp cao, thiết kế bài giảng sâu.
  • • Reasoning Core (DeepSeek-R1 / o1): Giải quyết logic toán học, lập kịch bản thực hành phức tạp.
  • • Small/Utility (Gemini 2.5 Flash / Llama 70B): Phân loại, gắn thẻ metadata, định dạng JSON. Cắt giảm 70% chi phí.
token

3. Skills (Gói nghiệp vụ đóng gói)

Đóng gói prompts hệ thống, validation logic, few-shot examples thành module kỹ năng có thể kiểm thử độc lập.

Tách biệt hoàn toàn với mã nguồn chính. Cho phép cập nhật prompts nghiệp vụ thông qua CI/CD và Git version control mà không cần build lại core orchestrator.

shopping_cart

4. Tools & Protocols (MCP, AP2)

Giao tiếp chuẩn hóa thông qua Model Context Protocol và thực hiện giao dịch an toàn tự động thông qua Agent Payments Protocol.

• Model Context Protocol (MCP): Cho phép LLM kết nối an toàn với kho dữ liệu chương trình học.

• AP2 (Agent Payments Protocol): Hợp đồng Intent Mandate ký số bởi giáo viên (ví dụ: tối đa $2.00) để tác nhân tự thanh toán mua bản quyền ảnh minh họa hoặc mô hình lab.

memory

5. Memory Systems

Hệ thống lưu trữ bộ nhớ ngắn hạn episodic (trạng thái phiên làm việc) và bộ nhớ dài hạn semantic (sở thích và phong cách giáo viên qua Vector DB).

Hạ tầng bộ nhớ ConnectED:

  • • Episodic: Tự động ghi nhận và khôi phục trạng thái soạn thảo dở dang của giáo viên khi mất kết nối mạng.
  • • Semantic: Lưu trữ phong cách hành văn, phương pháp đánh giá yêu thích của giáo viên để cá nhân hóa bài giảng tương lai.

Module 03

Vượt qua các rào cản trong kỷ nguyên Agentic

Xây dựng AI Agent chạy thử nghiệm thì đơn giản. Đảm bảo chúng hoạt động tin cậy, tiết kiệm chi phí và có khả năng giám sát (trace/observe) ở môi trường doanh nghiệp lớn mới là thách thức thực tế.

report_problem

01. Độ tin cậy (Reliability)

Ảo tưởng (hallucination) trong Agent dẫn đến hành động sai nghiêm trọng như gọi nhầm API, lặp suy nghĩ vô hạn.

Giải pháp Production-Grade:

• Ép buộc định dạng JSON cấp suy luận: Dùng JSON Mode hoặc Outlines để bảo đảm cấu trúc cú pháp 100% hợp lệ.

• Xác thực 2 tầng: Tầng 1 kiểm tra kiểu (Pydantic), Tầng 2 kiểm tra nội dung sư phạm thực tế (Bloom filter / Domain Index).

analytics

02. Đánh giá Quỹ đạo (Trajectory Eval)

Đánh giá tác nhân yêu cầu kiểm duyệt cả hành trình suy nghĩ, lập kế hoạch, gọi công cụ thay vì chỉ xem kết quả đầu ra.

Giải pháp Production-Grade:

• LLM-as-a-Judge: Hội đồng mô hình (sử dụng Claude 4.6 Sonnet làm giám khảo) đánh giá quỹ đạo dựa trên các rubrics điểm số định lượng.

• Golden Trajectory Suite: Lưu trữ >200 kịch bản thành công mẫu chạy hồi quy CI/CD tự động khi sửa prompts.

payments

03. Chi phí & Độ trễ (Cost & Latency)

Nhiều vòng lặp LLM tuần tự gây tăng chi phí token cấp số nhân và làm tăng thời gian phản hồi người dùng.

Giải pháp Production-Grade:

• Tối ưu cache: Sắp xếp system prompts MOET nặng lên đầu ngữ cảnh để tối đa hóa Prompt Caching, tiết kiệm đến 80% chi phí token.

• Lọc ngữ cảnh (Pruning): Thu hẹp ngữ cảnh RAG dưới 10k token, chạy song song các luồng độc lập giảm độ trễ 45%.

hub

04. Khả năng giám sát (AgentOps)

Trạng thái tác nhân biểu diễn bằng ngôn ngữ tự nhiên làm các chỉ số giám sát CPU/RAM truyền thống trở nên vô hại.

Giải pháp Production-Grade:

• OpenInference Tracing: Ghi nhận chi tiết từng bước LLM (Plan -> Act -> Observe) dưới dạng các Spans có cấu trúc.

• Cây thực thi (Execution Tree): Biểu diễn trực quan dòng chảy cuộc gọi phân cấp để gỡ lỗi và phát hiện thắt nút cổ chai (latency bottleneck).

Ví dụ code: Theo vết OpenInference trong Sản xuất

from openinference.instrumentation.llama_index import LlamaIndexInstrumentor
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import SimpleSpanProcessor
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter

# 1. Khởi tạo Tracer Provider
provider = TracerProvider()
trace.set_tracer_provider(provider)

# 2. Định cấu hình Export kết quả theo dõi sang Langfuse / Arize
otlp_exporter = OTLPSpanExporter(endpoint="https://api.langfuse.com/v1/traces")
provider.add_span_processor(SimpleSpanProcessor(otlp_exporter))

# 3. Kích hoạt tự động theo dõi (Auto-instrumentation)
LlamaIndexInstrumentor().instrument()

print("Agent telemetry active: Tracing Plan-Act-Observe spans.")
